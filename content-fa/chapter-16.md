# فصل ۱۶. پیکربندی هوش مصنوعی

وقتی چاپ اول این فصل را در سال ۲۰۲۴ می‌نوشتم پیش‌بینی کرده بودم که به‌سرعت قدیمی می‌شود و نگهداری‌اش کابوس خواهد بود. آن‌قدر درست بود که فکر نمی‌کنم هنوز خیلی‌ها از هیچ‌کدام از اکستراها و افزونه‌هایی که بحث می‌کرد استفاده کنند. آن را تا ژانویهٔ ۲۰۲۶ به‌روز کرده‌ام و احتمالاً دوباره بلافاصله قدیمی می‌شود.

چند گزینه برای ادغام هوش مصنوعی (AI) در کدنویسی روزمره دارید، از اجتناب کامل تا فقط-تکمیل تا تعامل‌های کاملاً تعاملی «سبک cursor». نمی‌توانم همه را این‌جا پوشش دهم، اما سعی می‌کنم بهترین نسخه‌های پشتیبانی‌شده در LazyVim را بزنم.

### ۱۶.۱. گردش‌کار فعلی هوش مصنوعی من از LazyVim استفاده نمی‌کند

من برای کار خیلی از هوش مصنوعی استفاده می‌کنم، اما برای کدنویسی تفریحی اصلاً. برای کار، منحصراً از قدرتمندترین ابزار خط فرمان روز استفاده می‌کنم. معمولاً Claude Code است، اما از Gemini CLI و Codex هم استفاده کرده‌ام.

در هر صورت، از LazyVim برای مدیریت پنجرهٔ هوش مصنوعی استفاده نمی‌کنم. فقط هرکدام را که استفاده می‌کنم در پنجرهٔ ترمینال جداگانه بیرون ویرایشگر اجرا می‌کنم.

حتی به خودم زحمت تکمیل‌های کد هوش مصنوعی داخل LazyVim را نمی‌دهم. آن‌قدر سریع تایپ می‌کنم که تکمیل‌ها عمدتاً بی‌فایده‌اند و منتظر ماندن برای ظاهر شدن مورد درست فقط کندم می‌کند.

علاوه بر این، وقتی با هوش مصنوعی کدنویسی می‌کنم، تکمیل‌ها کمک زیادی نمی‌کنند، چون فقط با ابزار CLI گپ می‌زنم. هیچ کدی برای تکمیل کردن وجود ندارد! و وقتی با هوش مصنوعی کدنویسی نمی‌کنم، دلیل خوبی برای نکردنش دارم و آن دلیل برای تکمیل‌ها هم صدق می‌کند.

با این حال، شما من نیستید و باید انبوه اکستراهای LazyVim را که پشتیبانی از کدنویسی هوش مصنوعی می‌دهند ارزیابی کنید تا ببینید کدام برای شما کار می‌کند. با تکمیل‌ها شروع کنیم.

### ۱۶.۲. Sidekick.nvim

افزونهٔ `Sidekick.nvim` توسط نویسندهٔ LazyVim نگهداری می‌شود، پس با همهٔ ابزارها و رابط کاربری که به آن عادت کرده‌ایم خوب جفت می‌شود. دو قابلیت نامرتبط هوش مصنوعی دارد:

- نمایش و پنهان کردن ابزارهای گپ CLI مثل Claude Code یا Codex داخل پنجرهٔ ترمینال در LazyVim.

- ادغام «پیشنهادهای ویرایش بعدی (Next edit suggestions)» از سرویس Copilot، با نمایشگر diff شیک و توانایی پذیرش و رد تغییرات.

اولی اگر بخواهید به‌جای رفتن به صفحه‌های ترمینال جدا مثل من، از LazyVim برای مدیریت پنجره استفاده کنید می‌تواند خوب باشد. پیشنهادهای ویرایش بعدی مثل تکمیل‌های درون‌خطی روی استروئیدند و ارزش فعال کردن را دارند اگر شما یا شرکتتان قبلاً روی Copilot سرمایه‌گذاری کرده‌اید. بیایید پیشنهادهای ویرایش بعدی (به‌اختصار NES، و اگر بگویم برای من یعنی کنسول بازی سنم لو می‌رود) را ببینیم.

#### ۱۶.۲.۱. پیشنهادهای ویرایش بعدی Sidekick

برای استفاده، اول افزونهٔ `ai.copilot` را همان‌طور که بالا توضیح داده شد فعال کنید تا وابستگی‌های لازم را بگیرید. بعد اکسترای `ai.sidekick` از Lazy را فعال کرده و ویرایشگر را دوباره راه‌اندازی کنید. بعد باید با دستور `:LspCopilotSignIn` احراز هویت کنید.

پیشنهادهای ویرایش بعدی به‌طرز شگفت‌آوری راحت‌اند، اما دانستن این‌که اصلاً کار می‌کنند یا نه می‌تواند سخت باشد. همان‌طور که مستندات افزونه می‌گوید، فقط باید «کمی کد تایپ کنید و مکث کنید - تماشا کنید که پیشنهادهای ویرایش بعدی ظاهر می‌شوند». با این حال، اگر کدی که تایپ کردید پیشنهادی را تحریک نکرد، آیا چون موتور نتوانست پیشنهاد خوبی بدهد یا چون کار نمی‌کند؟

من این کد پایتونِ به‌ظرافت خراب را برای تحریک قابل‌اعتماد NES مناسب یافتم:

فهرست ۵۸. پایتون کمی خراب

```text
def mean(numbers: int) -> float:
    return sum(numbers) / len(numbers) if numbers else 0
```

نوع پارامتر `numbers` نادرست است؛ باید `list[int]` باشد. NES ممکن است به‌محض مکث در تایپ تحریک شود، یا ممکن است لازم باشد `cw` روی `int` بزنید تا بداند دارید پارامتر را ویرایش می‌کنید، بعد زیر یک ثانیه مکث کنید، یا ممکن است لازم باشد `dw` بزنید و `Escape` را برای بازگشت به حالت عادی بفشارید. اگر خدایان هوش مصنوعی به شما لبخند بزنند، باید چیزی شبیه این ببینید:

![پیشنهاد ویرایش بعدی](/images/book/chapter-16/nes-dark.png)

شکل ۸۷. پیشنهاد ویرایش بعدی

خط بالا خطی است که فعلاً فوکوس دارد. زیر آن دو خط با هایلایت نارنجی‌مانند هستند. این‌ها جایگزینی پیشنهادی‌اند. آیکون ربات خندان کنارش هست (هرچند در فونت من بیشتر شبیه قورباغه به نظر می‌رسد). این نمادی است که LazyVim برای هوش مصنوعی انتخاب کرده. نشان می‌دهد که پیشنهاد ویرایش بعدی این‌جا دیده می‌شود.

خود پیشنهاد کمی ناامیدکننده است چون از `List` بزرگِ منسوخ استفاده می‌کند به‌جای `list` کوچکی که مدت‌هاست در پایتون استاندارد است. اما دست‌کم افزونه فعال است! حدس می‌زنم اگر طرح پولی Copilot برای فعال کردن مدل بهتر داشتم بهتر رفتار می‌کرد.

برای بردن مکان‌نما به نزدیک‌ترین NES، کلید `<Tab>` را بفشارید. اگر قبلاً روی پیشنهاد پیشنهادی هستید و می‌خواهید بپذیریدش، از همان کلید `<Tab>` استفاده کنید. پس می‌توانید هر پیشنهادی را با دو بار زدن `<Tab>` بپذیرید و به راهتان ادامه دهید.

پیشنهادهای ویرایش بعدی قرار نیست جای پیشنهادهای منوی تکمیل Copilot را بگیرند؛ احتمالاً می‌خواهید هر دو قابلیت را روشن کنید. NES می‌تواند بازسازی‌های (refactor) تهاجمی‌تری انجام دهد، در حالی که تکمیل‌ها فقط می‌توانند در یک نقطه (مکان‌نما) درج کنند، اما هر دو اگر هنوز کد تایپ می‌کنید مفیدند.

با این حال، اگر این روزها اهل هوش مصنوعی هستید، اصلاً چرا کد تایپ می‌کنید؟ این‌جاست که قابلیت دیگر Sidekick وارد می‌شود.

#### ۱۶.۲.۲. ادغام‌های گپ Sidekick

در زمان نوشتن، استاندارد طلایی برای کدنویسی با هوش مصنوعی، اگر شما یا کارفرمایتان حاضر به پرداخت باشید، Claude Code با مدل Opus 4.6 است. Anthropic واقعاً می‌فهمد چطور LLM را برای بیشترین اثر هدایت کند و در این‌که Claude Code چطور از ابزارهای دیگری که از مدل Opus استفاده می‌کنند بهتر عمل می‌کند دیده می‌شود.

استاندارد طلایی احتمالاً پیش از این‌که فرصت انتشار پیدا کنم عوض می‌شود، به همین دلیل خوب است که Sidekick از چند ابزار خط فرمان پشتیبانی می‌کند.

عمدتاً، رابط Sidekick به ابزارهای هوش مصنوعی فقط پوششی برای باز کردن ابزار منتخب در پنجرهٔ ترمینال نئوویم است. نکته‌های خوبی دارد، اما خلاصه همین است. برای استفاده، اول مطمئن شوید ابزار CLI هوش مصنوعی محبوبتان با دستورالعمل نصب پیشنهادی آن ابزار نصب است (چیزی می‌خواهید که درست خودبه‌روز شود چون این چیزها خیلی سریع تکامل می‌یابند).

همچنین مطمئن شوید Sidekick.nvim به‌عنوان اکسترای Lazy نصب است همان‌طور که قبلاً توضیح داده شد.

بعد از منوی `<Space>a` برای دسترسی به ابزارهای CLI استفاده کنید. مثلاً `<Space>aa` بوفه‌ای از ابزارها برای انتخاب نشان می‌دهد و دیدن این‌که کدام نصب‌اند را راحت می‌کند:

![منوی ابزارهای سایدکیک](/images/book/chapter-16/sidekick-tools-dark.png)

شکل ۸۸. منوی ابزارهای Sidekick

در این مثال فقط `codex` را نصب دارم (چون OpenAI آن‌قدر گرسنه بود که به من آزمایش رایگان بدهد).

ابزار خود را انتخاب کنید و در پنجرهٔ ترمینال جدیدی باز می‌شود که می‌توان همان‌طور که در فصل قبل توضیح داده شد در آن گشت. یادتان باشد، می‌توانید با `<Control-h>` و `<Control-l>` داخل و بیرون پنجره بروید.

مزیت اجرای یکی از این ابزارها در Sidekick به‌جای پنجرهٔ ترمینال جدا این است که می‌توانید نام فایل باز فعلی یا قطعهٔ انتخاب‌شدهٔ دیداری را با `<Space>af` یا `<Space>av` به آن بفرستید. علاوه بر این، دستور `<Space>at` «این را» می‌فرستد تا موقعیت فعلی مکان‌نما را بفرستد تا هوش مصنوعی بتواند به آن ارجاع دهد.

همچنین می‌توانید از میان چند پرامپت ذخیره‌شده انتخاب کرده و با `<Space>ap` بفرستید، اما راستش را بخواهم برای این‌جور چیزها دستورهای slash سفارشی یا مهارت‌ها (skills) را پیکربندی می‌کنم اگر مدل و بک‌اندتان از آن پشتیبانی می‌کنند. موارد ارائه‌شدهٔ Sidekick برای مدل‌های پیچیده‌ای مثل Opus کمی ساده‌اند و معمولاً ترجیح می‌دهم بگذارم هوش مصنوعی برایم مهارت بنویسد.

### ۱۶.۳. تجربه‌های کدنویسی خودکار داخل ویرایشگر

اگر دنبال تجربهٔ «شبیه Cursor» در ویم هستید، LazyVim چند اکسترای Lazy برای انتخاب دارد، از جمله copilot chat و avante.nvim. تجربهٔ اخیر زیادی با این‌ها ندارم اما سعی می‌کنم پوشش خوبی بدهم. آخرین باری که از Copilot Chat استفاده کردم (همان‌طور که در چاپ اول این کتاب مستند شد) پشتیبانی زیادی از ابزارهای عامل (agentic) نداشت، اما آن عوض شده. اکسترای Avante متأسفانه اصلاً برای من کار نکرد.

### ۱۶.۴. Copilot Chat

CopilotChat.nvim سعی می‌کند کدنویس را در کنترل نگه دارد و خیلی کمتر از ابزارهای کنسول خودکار است. راحت‌ترین تصور این است که ربات گپی است که می‌تواند با مدل‌های مختلف GitHub Copilot حرف بزند، و افزودنی فوق‌العاده به اکسترای copilot.lua است که تکمیل‌ها را می‌دهد.

کلیدبندها با موارد ارائه‌شده توسط sidekick.nvim تداخل دارند، پس احتمالاً خوب است اکسترای Sidekick را غیرفعال کنید اگر می‌خواهید از Copilot chat استفاده کنید.

اکسترا را به روش معمول فعال کنید و `<Space>aa` را برای تغییر وضعیت Copilot Chat بفشارید. اگر قبلاً احراز هویت نکرده‌اید URL و کدی می‌دهد تا در آن آدرس وارد شوید. به URL بروید و کد را وارد کنید.

حالا ربات گپی دارید که می‌توانید کارهای ربات گپی با آن بکنید (یعنی متن وارد کنید و پاسخ‌های تولیدشدهٔ دلخواه را بخوانید). فقط پیامی تایپ کنید و `<Control-s>` را بزنید (یا در حالت عادی `<Enter>` را بفشارید) تا پیام ارسال شود. زیبایی این پنجره، برخلاف پنجره‌های sidekick، این است که این یک بافر نئوویم است و همهٔ کلیدبندهای محبوب LazyVim برای ویرایش پیام در دسترس‌اند.

چند نویسهٔ جادویی هست که می‌توانید در گپ تایپ کنید تا زمینهٔ اضافی به گفت‌وگو بفرستید یا ذخیره کنید یا توابع دلخواه را فرا بخوانید. این‌ها با تکمیل تب تسهیل می‌شوند. عمدتاً، Copilot Chat به‌صورت خودکار چیزی را فرا نمی‌خواند یا اضافه نمی‌کند، و کنترل کامل (و مسئولیت) زمینه را به شما می‌دهد. برای استفادهٔ مؤثر، ضروری است که تکمیل‌های تب را یاد بگیرید.

مثلاً برای افزودن محتوای فایل به پیام، می‌توانید `#file:path/to/file.ext` را تایپ کنید. با این حال، این سریع خسته‌کننده می‌شود. به‌جای آن، فقط `#` را تایپ کنید تا منویی مثل این بگیرید:

![منابع گپ کوپایلت](/images/book/chapter-16/copilot-chat-resources-dark.png)

شکل ۸۹. منابع Copilot Chat

این‌ها همه *منابع (resources)*‌اند که می‌توان در گپ گنجاند. می‌توانید با کلیدهای جهت‌دار به `file` بروید و `<Enter>` را برای تکمیل بفشارید. حالا `:` و بعد `<Tab>` را تایپ کنید. کلید تب منوی انتخاب‌گر استاندارد با فایل‌هایی را نشان می‌دهد که می‌توانید برای افزودن به زمینه با جست‌وجوی فازی معمول جست‌وجو کنید. این راه کارآمد افزودن فایل به گپ است.

همان‌طور که از تصویر بالا می‌بینید، منابع دیگری هم هست که می‌توانید اضافه کنید و معمولاً منوی انتخاب‌گری دارند که می‌توان با میان‌بر `:` و بعد `<Tab>` فرا خواند. برخی منابع مفیدتر شامل این‌ها هستند:

- `#buffer:active` برای گنجاندن فعال‌ترین بافر اخیر

- `#buffer:visible` برای گنجاندن همهٔ بافرهای دیده‌شده در پنجره‌ها

- `#selection` برای گنجاندن آخرین انتخاب دیداری در بافر فعال

- `#url:<some url>` برای گرفتن محتوای وب

اگر می‌خواهید منبع چسبان (sticky) باشد (در یک نشست باقی بماند)، با `>` پیشوندش کنید مثل `> #buffer:active`. (این با متن دلخواه هم کار می‌کند اگر نوعی پرامپت سیستمی بخواهید).

مدل کل گفت‌وگو را با دستور `:CopilotChatModels` عوض کنید، یا اگر می‌خواهید فقط برای یک پیام عوض کنید می‌توانید درست در گفت‌وگو با تایپ `$` و بعد `<Tab>` مقتدر از انتخاب‌گر انتخاب کنید.

به چند پرامپت ازپیش‌تعریف‌شده با نویسهٔ `/` دسترسی دارید. همه را امتحان کنید! این‌جا پوشش نمی‌دهم، اما می‌توان با گسترش گزینه‌ها در پیکربندی افزونه پرامپت‌های خودتان را هم تعریف کنید.

به‌مراتب مفیدترین نویسهٔ جادویی دستور `@` است که به LLM دسترسی به ابزارها می‌دهد. ابزارها صرفاً فراخوانی‌های تابع lua هستند که LLM می‌تواند بر اساس تفسیرش از پیام شما انتخاب کند فرا بخواند. ساده به نظر می‌رسد، اما به رفتار استدلالی فوق‌العاده قدرتمندی منجر می‌شود. می‌تواند دستورها را اجرا کند، فایل‌ها و urlها را بخواند و کدبیس را جست‌وجو کند.

Copilot Chat برای اجرای هر ابزار از شما اجازه می‌خواهد و UX این کمی گیج‌کننده است. فراخوانی ابزار پیشنهادی را به پنجرهٔ گپ خروجی می‌دهد و باید پیام را با کلیدبندهای ارسال پیام `<Control-s>` در حالت درج یا `<Enter>` در حالت عادی تأیید کنید.

می‌توانید ابزارهای تکی را با مثلاً `@bash` مشخص کنید اما بیشتر اوقات فقط می‌خواهید از `> @copilot` استفاده کنید که همهٔ ابزارهای پیش‌فرض را در همهٔ پیام‌های آینده فعال می‌کند (`>` آن را چسبان می‌کند، یادتان هست). این به LLM اجازهٔ انواع عمل‌ها (از جمله ویرایش کدبیس شما) را می‌دهد.

می‌توانید توابع خودتان را هم تعریف کنید. اگر بخواهید خیلی فانتزی شوید، می‌توانید تابعی بسازید که عامل برنامه‌ریزی Claude را تقلید کند. محتمل‌ترین ابزاری که دسترسی می‌خواهید جست‌وجوی وب است، که برای آن کلید API با سرویسی مثل Tavily، Firecrawl یا Exa لازم دارید. این‌جا مثال تابع lua برای جست‌وجوی وب Exa آمده است:

فهرست ۵۹. تابع جست‌وجوی Exa برای Copilot Chat

```text
return {
  "CopilotC-Nvim/CopilotChat.nvim",
  opts = {
    functions = {
      websearch = {
        description = "Search the web for some query",
        uri = "search://{name}",
        schema = {
          type = "object",
          required = { "query" },
          properties = {
            query = {
              type = "string",
              description = "What to search for",
            },
          },
        },
        resolve = function(input)
          local curl = require("plenary.curl")
          local res = curl.post("https://api.exa.ai/search", {
            headers = {
              ["Content-Type"] = "application/json",
              ["Authorization"] = "Bearer " .. os.getenv("EXA_API_KEY"),
            },
            body = vim.fn.json_encode({
              query = input.query,
              num_results = 3,
            }),
          })

          if res.status ~= 200 then
            return { { error = "Exa API error: " .. (res.body or res.status) } }
          end

          local data = vim.fn.json_decode(res.body)
          local results = {}

          for _, item in ipairs(data.results or {}) do
            table.insert(results, {
              title = item.title,
              url = item.url,
              summary = item.summary,
            })
          end

          return results
        end,
      },
    },
  },
}
```

Copilot Chat خوب است اگر بخواهید کنترل بیشتری روی این‌که چه ابزارهایی فرا خوانده می‌شوند داشته باشید تا ابزارهای CLI که sidekick به آن‌ها دسترسی می‌دهد. به نظر می‌رسد الان بهترین پشتیبانی را در LazyVim دارد، اما مسئولیت بررسی هر افزونه اگر به خودکارسازی ابزارهای CLI مثل Claude Code عادت دارید کمی خسته‌کننده است.

### ۱۶.۵. نکته‌ای دربارهٔ Avante.nvim

Avante تلاشی است برای این‌که نئوویم بیشتر شبیه ابزار کدنویسی خودکار مثل Cursor رفتار کند. در چند تلاش طی یکی دو سال گذشته نتوانستم وادارش کنم رفتار کند.

حتی با اکسترای Avante در LazyVim، حتی نتوانسته‌ام پرس‌وجویی صادر کنم. کاملاً مطمئنم که اکسترا باید به‌روز شود تا از Snacks پشتیبانی کند تا اصلاً کار کند. سعی می‌کنم این بخش را به‌روز کنم اگر نسخهٔ جدید اکسترا بیرون بیاید، اما در حال حاضر ارزش تلاش لازم برای درست کردنش را ندارد.

### ۱۶.۶. Code Companion.nvim

Code Companion افزونهٔ نئوویم خوش‌نگهداری و خوش‌مستندی است که کمی خودکارتر از Copilot Chat است (با دسترسی به ارائه‌دهندگان مدل بیشتر) و کمی کمتر خودکار از Avante، دست‌کم برداشت من از این‌که Avante قرار است چطور کار کند.

آن را برای کامل بودن ذکر می‌کنم چون احتمالاً بهترین افزونهٔ هوش مصنوعی است که اکسترای LazyVim ندارد. فعال کردنش با دستورالعمل نصب مستند راحت است؛ فقط این را در فایلی در دایرکتوری lua/plugins بیندازید:

```text
return {
  "olimorris/codecompanion.nvim",
  version = "^18.0.0",
  opts = {},
  dependencies = {
    "nvim-lua/plenary.nvim",
    "nvim-treesitter/nvim-treesitter",
  },
}
```

با این حال، این ادغام واقعی LazyVim نیست. هیچ کلیدبندی برای تحریک which-key یا دستوری برای تحریک بارگذاری تنبل تنظیم نمی‌کند و پنجره را مثلاً با edgy.nvim ادغام نمی‌کند. چون شخصاً از افزونه استفاده نمی‌کنم، پیکربندی درستی برایش ندارم، اما اگر پیکربندی خوبی ساختید به من بگویید تا این‌جا بگنجانم. بهتر از آن، ببینید می‌توانید PRای بگذارید تا به‌عنوان Lazy Extra پذیرفته شود!

برای اطلاعات دربارهٔ نحوهٔ واقعی استفاده از افزونه به [مستندات عالی Code Companion](https://codecompanion.olimorris.dev/) ارجاع می‌دهم. خیلی شبیه Copilot Chat رفتار می‌کند، هرچند ادغام‌های عاملی‌اش کمی صیقلی‌ترند.

### ۱۶.۷. اکستراهای دیگر هوش مصنوعی LazyVim

چند اکسترای LazyVim زیر فضای نام ai هست که می‌توانید امتحان کنید. هشدار می‌دهم که بیشترشان افزونه‌های نسبتاً قدیمی‌اند و حتی اگر افزونه نگهداری شود، ادغام LazyVim کهنه شده است.

- claudecode.nvim تلاش می‌کند افزونهٔ VSCode را با باز کردن اتصال وب‌سوکت به CLI تقلید کند و از نظر تئوری می‌تواند بهتر از پوشش ترمینال با NeoVim ادغام شود.

- فکر نمی‌کنم اکسترای ai.codeium دیگر کار کند؛ نصب می‌شود اما نتوانستم احراز هویت کنم. فکر می‌کنم اکسترا باید به‌روز شود تا در فضای نام windsurf کار کند.

- supermaven-nvim دو سال است به‌روز نشده

- ai.tabnine هم به‌روزرسانی اخیر ندیده است.

قبلاً همهٔ این‌ها را مستند می‌کردم، اما در این نقطه Claude code و ابزارهای CLI دیگری که دیوانه‌وار سعی می‌کنند به آن برسند به‌راحتی از همهٔ آن‌ها پیشی گرفته‌اند.

### ۱۶.۸. جمع‌بندی

این فصل همه دربارهٔ هوش مصنوعی بود. هوش مصنوعی با توجه به پیچیدگی‌ای که انتزاع می‌کند موضوع عجیبِ ساده‌ای است. زیر کاپوت، LLMها واقعاً جذاب‌اند، اما رابط تعامل با آن‌ها معمولاً فقط یک درخواست سادهٔ HTTP به APIای جایی است (APIای آن‌قدر مفید که جمعاً به‌اندازهٔ کافی سخت فکر نمی‌کنیم که چقدر به آن اعتماد می‌کنیم).

افزونه‌های مختلف نئوویم رابط‌هایی به این APIها ساخته‌اند. LazyVim ادغام برخی را با blink.cmp راحت می‌کند و سرویس‌های دیگر با افزونه‌های ثالث پوشش داده می‌شوند.

انتخاب بین گزینه‌های مختلف بخش سخت است. هیچ‌کدام کاملاً آن‌طور که می‌خواهم کار نمی‌کنند و می‌بینم زمانی که صرفه‌جویی می‌کنند تقریباً برابر زمانی است که وقتی اشتباه می‌کنند هزینه می‌کنند.

بعد، دربارهٔ اجرای دیباگرها از داخل LazyVim بحث می‌کنیم.
